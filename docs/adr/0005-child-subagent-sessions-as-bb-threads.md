# Дочерние субагенты как треды bb

RLM-дети resident-сессии, привязанной к bb-потоку, появляются в bb как
отдельные треды-потомки: плагин сам создаёт их через `bb.sdk.threads.spawn`
(`parentThreadId` = тред родителя, `origin: plugin`), тред называется именем
ребёнка, лента наполяется транскриптом ребёнка, новые сообщения можно писать
ребёнку напрямую. Ряды делегации в ленте родителя и панель Subagents
остаются: они — история родителя и ростер, тред-ребёнок — глубокое окно.

Ключевой приём — **маркерный первый диспатч**. `threads.spawn` требует input,
а реальный промпт ребёнку слать нельзя, поэтому спавн кладёт в input
agent-only-маркер с id сессии ребёнка. Мост поглощает маркер в `thread/start`
(до модели он не доходит никогда), регистрирует запись с providerThreadId
ребёнка и делает attach — семантика «усыновлённой» сессии реплеит транскрипт
ребёнка в свежий тред, дальше всё едет на существующих механизмах: переводчик
сам открывает turn'ы на `agent_start` (фоновая активность prime уже течёт так),
промпты пользователя идут обычным путём против сессии ребёнка, эвикшн
переоткрывает сессию из транскрипта. bb хранит связь тред↔сессия через
`thread/identity`, так что resume и перезапуски моста работают без отдельного
состояния.

## Жизненный цикл и границы

- **bb не уничтожает чужое**: `thread/stop` на треде ребёнка только
  отвязывает (release); cancel ребёнка — из панели Subagents
  (`cancel_rlm_child`), как и раньше.
- **Имя**: заголовок треда = label ребёнка из prime, сплющенный в одну
  строку и ограниченный 64 символами — prime ставит безымянным детям в
  label весь текст задачи, и дословный label превращает заголовок в промпт
  (наблюдено вживую 2026-09-07). Переименование — локально в bb и в prime
  не уходит.
- **Идемпотентность**: в пределах процесса — множество заспавненных id
  сессий; после перезапуска сервера — скан `threads.list({parentThreadId})`
  по совпадению заголовка (коллизия двух живых детей с одинаковым display
  name у одного родителя сознательно допустима: задвоение лучше тишины).
  Заголовок — `sessionName` ребёнка из ledger (`explorer`, `impl-7c4-1`);
  label — только fallback, и то и другое приводится к одной строке ≤64
  символов: label безымянного ребёнка — это весь текст задачи, промпт не
  должен становиться заголовком. Это же display name идёт в label
  delegation-item в панели Subagents.
- **Watch**: спавн будит глобальный push `subagents.changed`; чтобы он шёл,
  сервер держит watch на сессиях недавних bb-тредов (медленный скан списка
  тредов + резолв identity) и на сессиях, отрезолвленных панелями. Дети
  сессий, ни разу не попавших в поле зрения сервера, всплывают только после
  первого watch — v1-ограничение, сознательно не решаемое постоянным
  опросом всего каталога.

Известное следствие дедюпа по заголовку: если формат заголовка меняется
между релизами плагина, существующий тред ребёнка перестаёт совпадать и
ребёнок получает второй тред (наблюдалось при переходе на capped-title).
Надёжный дедюп — по маркеру в `titleFallback` — кандидат на v2.

Известный quirk bb 0.42.1: `deriveTitleFallback` в сервере не фильтрует
agent-only-части (в отличие от видимого текста в db-слое), поэтому маркер
попадает в `titleFallback` треда. Пока `title` непустой — а мы кладём его
всегда — fallback нигде не виден; кандидат на апстрим-фикс.

Этим же решением закрывается смысл отложенного тикета «UI attach to existing
resident sessions» (bbpa-b1m.7): сессия, созданная не bb, теперь попадает в
bb как тред-ребёнок без отдельной UI-поверхности attach.

## Considered Options

- Апстрим-фича «resume в new-thread flow» — правильный UX для произвольных
  сессий, но это чужой репозиторий и другие сроки; плагинный путь доступен
  сейчас.
- Спавн без input через `sendAt`/hook hold — тред навсегда остаётся
  pending/queued, видимые артефакты в UI хуже маркерного диспатча.
- Рисовать детей только в панели (v1-статус-кво) — теряется главный смысл:
  ребёнок как полноправный разговор.
